# How this deck's files are written (Claude Slides type)

Everything below comes from the Slides type's own instructions. Follow it exactly: the deck page drops anything outside
this subset.

## Files

Write under the deck root folder (this folder's parent of `project/`):

- `project/deck.json`, the index:
  `{"v":4,"createdOnFiles":{"v":1,"at":"<now, RFC 3339>"},"lists":"css","title":"<deck title>","order":["cover", ...],"sections":{"<key>":{"description":"<one sentence>","start":"<first slide id>"}},"faces":{"dm-sans":{"family":"DM Sans","href":"https://fonts.googleapis.com/css2?family=DM+Sans:wght@300..700&display=swap"}, ...},"designSystems":[]}`
  `order` names every slide id in deck order. `sections` is the outline; the first starts at the cover. Ids:
  `[A-Za-z0-9_-]{1,64}`. `faces`: at most 4, keyed by family lowercased with spaces as `-`, each `{family, href}` with an
  `https://fonts.googleapis.com/css2?...` link.
- `project/slides/<id>.html`, one per slide: EXACTLY ONE `<section id="<id>" ...>` and nothing before or after it (no html,
  head, title, link, style or body). The section's `id` equals the file name. Speaker notes: plain text in one `<aside>`,
  the section's LAST child, at most 4,000 characters.
- Write each file directly with the file-writing tool (not generated by a script).
- Images: none from the web. Use SVG, shapes and live embeds.

## The slide format

A slide is a `<section id="..." style="...">` on a fixed 1920x1080 px canvas. Every style is inline, from a closed
subset: px lengths, hex or rgb colours, no classes, no `<style>`, no `margin`, no `z-index`, no `em`, no `var()`.

- On the section: `background` (always), the text defaults (`font-family`, `color`), and the layout:
  `display:flex; flex-direction:column` or `display:grid`, `padding:128px` (the margins: 1664x824 inside), `gap`,
  `align-items`, `justify-content`.
- Children flow in it. `position:absolute` pins a child to the slide instead: `left`/`top`/`right`/`bottom`/`width`/
  `height`. Give pinned text a `width`. Later children paint over earlier ones, so a full-bleed backdrop comes first.
- Elements, written in reading order:
  - Text: `<h1>` `<h2>` `<h3>` `<p>`. Set `font-size`, none under 24px. A block's title is `<h3>`. Defaults are
    96/64/44/32px.
  - `<ul>`/`<ol>` of plain `<li>`, one level only. `<br>`.
  - Inline only: `<b>` `<i>` `<u>` `<a href>` `<span style="color:...">`. No sizes or fonts on spans.
  - `<div>` containers: a flex row, column or grid, at most 15 deep. A div is invisible unless painted (`background`,
    `border` or `box-shadow`).
  - `<img src alt style>`, `<table>` of `<tr>`/`<th>`/`<td>`, `<hr>`.
  - `<svg aria-label>`: at most 52 KB, no script. Labels inside an svg don't get the deck's fonts, so put text in `<p>`s
    pinned over it.
  - `<x-shape kind="rect|rounded|ellipse|diamond|arrow-right|arrow-left|arrow-up|arrow-down|line">`.
  - `<x-icon name>` (Activity Book Chart Chat Check CheckCircle Clock Cloud Code Database Globe GraduationCap Home Key
    Lightbulb Lightning Link Lock PaperPlane Play Search Settings Star ThumbsUp Tool Trust Users Verified Warning Wrench).
  - `<x-connector>`.
- **Live embed:** `<x-embed style="position:absolute; left; top; width; height">...a whole small page...</x-embed>`.
  - It is a sandboxed iframe: scripts run; no network; `font-src data:` only.
  - It must be a DIRECT child of `<section>` and pinned. At most 16 KB each, at most 8 per slide.
  - The deck's fonts and styles don't reach it, so use a system font stack inside it. Its background is transparent
    until painted, and viewers can't click or type into it.
  - Keep its text at least 24px.
  - PPTX/PDF flatten it; the web page runs it. Use embeds for the animated data style slides: CSS keyframes or a few
    lines of JS that draw and animate an SVG chart on load.
- Motion: `data-transition="fade|push|magic"` on a section, `data-build-in="fade|rise|pop"` on pinned children.
- At most 200 elements per slide.

Supported CSS, in short:
- Sizing and position: `position`, `left`/`top`/`right`/`bottom`, `width`, `height`, `min-*` and `max-*`.
- Layout: `display` (flex, grid, none), `flex-direction`, `flex-wrap`, `gap` (0 to 512), `align-items`,
  `justify-content`, `justify-items`, `align-self`, `flex`, `grid-template-columns` and `-rows` (px, fr, auto,
  repeat; no minmax), `grid-column`/`grid-row` (span N only), `aspect-ratio`, `padding` (0 to 256), `overflow`.
- Type: `font-family`, `font-size` (8 to 400), `font-weight`, `font-style`, `line-height`, `letter-spacing`,
  `text-align`, `text-transform`, `white-space`, `text-decoration`, `font-variant-numeric`.
- Paint: `color`, `background` (colour, linear or radial gradient), `border` (style word required),
  `border-radius`, `box-shadow`, `text-shadow`, `opacity`, `transform` (translate, rotate, scale 0.5 to 2, skew),
  `filter`, `backdrop-filter`, `mix-blend-mode`, `object-fit`.

## Designing it

- Hex colours, once per deck: one dark, one light, and 1 or 2 accents. Use toned whites and blacks, two background
  tones, and one accent statement slide. Set `background` on every section.
- Contrast: text at least 4.5:1, or 3:1 at 44px and up.
- One type scale of four or five sizes, with 1 to 3 typefaces.
- One idea per slide. Turn lists into tables, card rows, big numbers or quotes. Titles introduce the topic in one
  grammar throughout.
- Vertical space is 824px inside the margins. Estimate sizes: a heading is about size x lines x 1.1, and a table row
  about 2.1 x the font size per line. Text wraps only at spaces, so size boxes to their longest word (about 0.6 x the
  font size per character). If a slide is too full, split it; never shrink.
- Footer band: one pinned 24px row at `bottom:64px`, and that slide gets `padding:128px 128px 160px`.
- Rhythm: the heading sits at the top margin, and slides of one kind share markup.
- Typographic punctuation in text people read: use curly apostrophes and curly quotes.
